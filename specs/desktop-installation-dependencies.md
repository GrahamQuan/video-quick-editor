# 桌面安装包与第三方媒体依赖规格

状态：已实现 DMG 构建与统一依赖阻断（2026-09-08）。发布签名、公证和公开下载后的安装验收未完成；实际验证记录见第 9 节。

## 1. 目标与关系

提供可安装的 macOS 桌面应用，用户下载 DMG 后将应用拖入 Applications 即可完成应用安装，不需要 Node.js、pnpm 或源码环境。FFmpeg 与 ffprobe 始终是外部第三方依赖，不放入应用或安装镜像，不由应用下载或自动安装。

本文补充 [Agent 视频编辑规格](agent-video-editing.md) 和外部 [基础桌面规格](/Users/a6677/Documents/personal-projects/learn-python-monorepo/specs/video_tools_spec.md) 的安装及依赖可用性合同；不修改外部仓库。“一键安装”在本期指便捷的 DMG 拖入安装，不承诺静默安装、自动安装 FFmpeg 或绕过 macOS 的系统确认。[多模型规格](multi-model-chat.md) 的配置与连接测试不依赖 FFmpeg。

## 2. 当前基础与范围

实施前 electron-builder 仅生成 macOS arm64 `dir`。现在 `pnpm package` 生成 DMG，`pnpm package:dir` 保留目录产物；统一依赖状态服务接入媒体入口和队列执行。

本期提供 macOS Apple Silicon 的 DMG 与可用于本地测试的 `.app`。Intel、Universal、Windows、Linux 安装包和自动更新不在本期；不得将 arm64 产物标为通用版本。

不新增 Homebrew 安装器、依赖下载服务、FFmpeg WASM、Python 或网络媒体处理服务。应用升级/替换保留原 appId 和 userData 位置，不删除设置、模型配置或凭证；不扩大现有会话持久化能力。

## 3. 打包与安装合同

| 项目           | 目标行为                                                                                        |
| -------------- | ----------------------------------------------------------------------------------------------- |
| 用户安装产物   | `Video-Quick-Editor-<version>-mac-arm64.dmg`，包含 `.app` 和 Applications 快捷入口              |
| 应用名称       | `Video Quick Editor.app`；沿用既有 bundle identifier                                            |
| 包含内容       | Electron runtime、应用代码、必要 JS 依赖及应用资源                                              |
| 排除内容       | ffmpeg/ffprobe 可执行文件、媒体处理依赖安装器、开发缓存、测试视频、用户设置、模型 key、用户媒体 |
| 安装过程       | 挂载 DMG，拖入 Applications，启动；无需开发工具链                                               |
| 缺依赖首次启动 | 应用仍可打开，显示检测及缺失状态，不崩溃、不尝试自动安装                                        |

目标命令：`pnpm package` 构建面向用户的 DMG；保留或新增 `pnpm package:dir` 仅生成 `.app`，供本地验收使用。`pnpm test:e2e` 继续使用 dir 构建，不为每次自动测试制作 DMG。这些命令已由根脚本及桌面 package 实现。

产物必须从受控构建输出生成，检查 `.app` 与镜像内容没有 FFmpeg/ffprobe 副本，也没有凭证或测试 fixture。当前 ad-hoc 签名用于本机测试，不能当作 Developer ID 签名或公证。没有发布凭证时产物明确标记未完成发布签名/公证，不承诺下载后无系统提示；面向公开分发的无额外阻碍安装体验须另行完成签名、公证与下载场景验收。不自动关闭系统安全检查。

## 4. 依赖状态与发现

由 main 维护统一依赖状态并通过 typed IPC 发布。目标状态为 `checking`、`ready`、`unavailable`；首次检测完成前视为不可启动媒体处理，不沿用磁盘中旧的 ready 标记。

每个工具的检测结果包含工具标识、可用版本、失败分类和必要能力的缺失列表。完整本地路径只用于本机设置与诊断，不进入模型上下文。分类至少区分：未找到、不可执行、架构不兼容/启动失败、检测超时、缺失编码器、缺失滤镜。

发现顺序：用户明确配置的路径优先；未配置时检查既有常见安装位置和可用 PATH。用户配置的路径失效时明确提示，不悄悄改用另一份二进制。Finder 启动不能依赖交互 shell 的初始化文件。通过“选择工具路径”可分别选择 ffmpeg 和 ffprobe，保存后立即重新检测。

检测须实际运行版本及能力查询，不能只检查文件存在。检测进程使用结构化参数、`shell: false`，有有界超时并在超时后结束进程；并发重新检测采用版本/序号防止旧结果覆盖新设置。检测命令本身允许在 unavailable 状态执行。

就绪要求 ffmpeg、ffprobe 都能运行，并包含应用完整媒体工作流所需能力。本期沿用严格的整体阻断：即使某次 copy 理论上不需要编码器，只要基础工具链不完整，也不启动媒体操作。编码器至少包含当前要求的 libx264、libx265、aac；滤镜集合必须覆盖实际 planner/proxy/frame-preview 所用功能，包括当前检测的 drawtext、concat、scale、pad、fps，以及 trim/时间戳、像素格式、SAR、音频裁剪/重采样/补静音链路。实施时从实际参数构建路径核对并用测试固定，不能只沿用不完整的字符串存在检查。

字体继续使用独立的系统字体/手动选择与字形校验流程；缺少适用字体不是 FFmpeg 安装失败。

## 5. 缺失依赖时的行为

状态条使用统一的中英文文案，列出实际缺失项，例如：

> 缺少第三方依赖：FFmpeg / ffprobe。请安装依赖或在设置中指定工具路径，完成后重新检测。

只缺某个工具或某项能力时准确列出它，不笼统宣称 FFmpeg 未安装。提供“打开设置 / Open settings”“选择工具路径 / Choose executable”“重新检测 / Check again”。安装指引可提供说明与用户主动打开的官方文档链接；应用不执行安装命令，不下载二进制，不反复弹窗。

| 操作                                           | checking / unavailable 时                                     |
| ---------------------------------------------- | ------------------------------------------------------------- |
| 打开应用、切换页面、设置语言                   | 允许                                                          |
| 管理模型、切换模型、无副作用连接测试、清空聊天 | 允许                                                          |
| 查看已有素材信息、编辑已知范围/排序/水印参数   | 允许，不运行媒体处理；原片播放器仍可尝试播放                  |
| 文件选择、拖入、纯路径导入、聊天自动路径导入   | 不启动 ffprobe 或媒体生成，不注册未探测素材；给出同一依赖提示 |
| 生成 proxy、缩略图或真实导出帧                 | 禁止启动 FFmpeg；已有有效缓存可读取                           |
| 创建可执行导出计划、提交导出、队列开始执行     | 阻止并返回依赖错误，不创建伪成功任务                          |
| 取消已有任务、查看历史结果、打开已有输出       | 允许；不因依赖缺失删除已有结果                                |

UI 禁用相关入口并展示原因，但不能只靠按钮禁用。所有原生 IPC 和 Agent tool 必须经过 main 的同一依赖检查；直接调用接口也不能绕过。Agent 可以继续文字交流、读取现有上下文或修改无需媒体进程的草稿，相关媒体工具返回 `TOOLS_UNAVAILABLE` 及可修复摘要，不声称剪辑或导出已完成。包含“导入路径并剪辑”的请求在本地导入阶段即停止，不向模型发送一次注定缺少素材的编辑请求。

## 6. 执行时重验与恢复

启动、用户保存工具路径、点击重新检测时检查依赖；每次启动实际媒体处理前，main 对本次使用的工具路径及状态重新验证。已有计划不能作为永久可用性凭据，不能因为启动时 ready 就在工具被移除后继续提交任务。

本期不做自动无限重试或无限排队等待安装。导出入队时缺依赖应直接拒绝；已排队、尚未运行的任务在真正启动时发现缺失，则以明确依赖错误结束为失败，保留草稿和现有文件。正在执行的任务固定启动时的工具路径和参数；设置变化只影响后续操作。进程实际失败按既有错误/清理流程处理，不强行杀掉正常运行的任务来应用新设置。

检测成功后立即更新所有页面、按钮和工具可用性，无需重启。不自动重放之前被阻止的导入、模型请求或导出；用户再次执行。导入失败不产生半条素材，取消/失败只清理本次临时输出，不触碰源文件或已有目标。

## 7. 代码归属与接口

- `packages/shared/src/index.ts`：依赖状态、失败分类、查询/更新 IPC 的 Zod 合同；不引入 Node API。
- `main/`：统一发现与检测服务、状态订阅、可用性守卫、实际媒体入口及队列启动前重验；保留源文件和输出保护。
- `preload/`：窄 typed API；不给 renderer 或模型任意执行权限。
- `renderer/`：全局依赖提示、控件阻断与设置恢复流程，通过 `i18n.ts` 保持双语一致。
- `packages/media-core/`：接受显式工具路径，保留自身错误和结果验证；不依赖 Electron 全局状态，不下载安装工具。
- electron-builder 与根脚本：DMG 和 dir 产物职责分开，不将检测代码变成依赖安装代码。

## 8. 验收标准

1. 制作 DMG，挂载后可拖入 Applications，并从 Finder 启动；目标架构和版本正确，运行应用不要求 Node.js/pnpm。
2. 检查 DMG 和 `.app` 不包含 FFmpeg/ffprobe、测试媒体、个人设置或 API key。记录签名/公证实际状态，不以本机 ad-hoc 验证替代下载后验收。
3. 使用隔离测试环境模拟两个工具都缺失、只缺一个工具、无执行权限、错误架构、超时、缺编码器/滤镜。应用仍可启动且提示具体原因。
4. 每种缺失状态下，UI、直接 IPC 和 Agent 媒体工具均不能启动实际媒体处理；只允许依赖检测进程。设置和模型连接测试仍可使用。
5. 依赖缺失时，选择器/拖放/路径列表/一句话路径导入都不会注册未探测素材；计划和导出入口没有假成功，也没有新建临时输出。
6. 指定可运行工具并重新检测后，不重启即可恢复导入和导出；不自动重放先前请求。覆盖中英文和窄窗口提示。
7. 启动检测成功后模拟移除工具、替换为不完整版本、修改设置或令队列启动检查失败，验证重新校验和任务状态；源文件及已有目标保持不变。
8. 在可用依赖下，用临时 lavfi fixture 完成一次真实导入、裁剪/拼接、水印和 MP4 导出，经 ffprobe 验证，证明阻断恢复没有破坏正常链路。
9. 替换已安装应用后，语言、工具路径与模型配置保留；不宣称尚未实现的聊天或项目跨重启恢复。

自动验证使用注入的发现候选、受控假可执行程序和临时 userData/Downloads，不能卸载、重命名或修改开发者机器上的系统 FFmpeg 来模拟缺失。保留真实媒体集成测试与 Electron 交互测试。DMG 挂载、Finder 启动及公开下载后的签名场景单独记录。实施完成时同步更新两份 README 的安装流程、产物位置和限制。
