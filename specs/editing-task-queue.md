# 裁剪、组合选择与串行任务队列规格

状态：已实现，2026-09-10 通过离线自动验证；覆盖范围与未验证项见第 10 节。

## 1. 目标与范围

用户可以连续加入多个独立的「裁剪」任务、多个独立的「组合」任务，也可以混合加入同一个队列。队列按入队顺序处理，一次只执行一个导出任务。排队或导出期间，用户仍可选择其他素材、调整范围并提交下一项任务。

修正“导入多个视频就强制组合”的交互：素材库数量只决定功能是否可用，不决定用户当前在做裁剪还是组合。只有本次任务明确选中的片段才参与输出。

本文补充 [Agent 视频编辑规格](agent-video-editing.md) 和 [桌面安装与依赖规格](desktop-installation-dependencies.md)，并更新外部 [基础桌面规格](/Users/a6677/Documents/personal-projects/learn-python-monorepo/specs/video_tools_spec.md) 中由片段列表数量隐式决定编辑流程的规则。底层继续复用有序片段、计划和导出引擎，不建立两套媒体处理实现，不修改外部仓库。

本期不包含跨重启恢复、定时执行、暂停后断点续跑、队列拖动排序或一个任务依赖另一个任务的输出。裁剪仍指时间范围裁剪，不是画面裁切。

## 2. 当前基础与问题

当前 `main/index.ts` 使用 Promise 链串行执行导出，并保存请求快照。新任务在等待时就标记为 `validating`，不能准确表达排队状态。现有任务基础应复用，但要完善明确的等待状态、取消行为和统一调度入口。

需要区分四个概念：

| 概念         | 含义                                               |
| ------------ | -------------------------------------------------- |
| 素材库       | 当前会话已成功导入的全部视频，不等于本次输出内容   |
| 当前预览片段 | 用户正在查看和调整 start/end、水印的片段           |
| 本次任务片段 | 裁剪中的一个片段，或组合中明确选中的有序片段       |
| 队列任务     | 已提交的不可变请求快照，拥有独立 jobId、状态和输出 |

点击素材用于预览；勾选素材用于加入组合。两者必须分开，不能通过切换预览悄悄改变组合内容。

## 3. 文件数量与 Tab 规则

数量边界已由用户确认：**2 个文件即可组合，3 个及以上显示多选**。这里的数量 N 指当前会话素材库中已成功导入的视频素材记录数，不是本机目录中的文件总数，也不是排队任务数或重复片段数。未导入文件不扫描、不计数，探测中或导入失败的文件不计数。

| 素材数量 N | 裁剪 Tab             | 组合 Tab | 组合选择方式                                               |
| ---------- | -------------------- | -------- | ---------------------------------------------------------- |
| 0          | 可显示空态，不能提交 | 禁用     | 展示导入提示                                               |
| 1          | 可用                 | 禁用     | 提示“至少导入 2 个视频才能组合”                            |
| 2          | 可用                 | 可用     | 首次进入时默认使用这两个文件；清楚显示参与组合的两项及顺序 |
| ≥ 3        | 可用                 | 可用     | 显示复选框、已选数量、全选和清空选择；只使用选中项         |

初次导入后默认停留在「裁剪」，即使一次导入多个视频也不自动切到「组合」。从 1 个增加到 2 个或更多，只解锁组合入口，不切换当前 Tab。

首次在 N ≥ 3 时进入组合，默认不勾选任何素材，由用户明确选择。已有组合选择时，继续导入新文件保留原选择，新文件默认不勾选。由 N = 2 增加到 N = 3 时保留原两项并显示复选框。

组合已选少于 2 项时，Tab 仍可用，但“加入组合队列”禁用并说明“至少选择 2 个片段”。不能用其他未选素材自动补足。

素材移除后，清除它在尚未提交的组合选择中的引用；若素材库仍有至少 2 项，保留组合 Tab，由用户补选。若素材库少于 2 项，则组合 Tab 禁用并回到裁剪，显示原因。已经入队的任务按第 6 节的快照规则处理。

Tab 使用可访问的选中/禁用状态，键盘操作遵守同样规则；中英文文案和窄窗口布局一致。

## 4. 裁剪与组合编辑

### 4.1 裁剪

裁剪 Tab 一次编辑一个明确的当前片段。即使素材库有多个视频，“加入裁剪队列”也只提交当前片段，生成一个任务和一个输出文件。

用户可选择 A、调整范围、入队，再选择 B、调整范围、入队；两次提交生成两个独立裁剪任务，不合并为组合任务。同一源视频也可设置不同范围多次入队。

当前片段的时间刻度拖动与 start/end 输入保持双向同步。切换素材时恢复各片段的范围和水印，不把上一项的时间范围直接套到下一项；新片段默认完整时长。

### 4.2 组合

N ≥ 3 时在素材列表显示多选入口。勾选和取消勾选立即更新“已选 X 项”、组合顺序列表和总输出时长；“全选”选择当前素材库中的全部项，“清空选择”只清除组合成员，不清空素材或队列。

首次勾选按素材列表的可见顺序排列，不按点击先后随机改变顺序。选中列表支持明确排序；已有项保留用户调整后的顺序，后续新增选中项追加到末尾。取消勾选后再次选中视为追加。

每个组合片段可独立设置 start/end 和水印；点击未勾选素材进行预览，不会把它自动加入组合。取消勾选不会丢失该片段尚未提交的范围设置。

“加入组合队列”把当前选中的有序片段组成**一个**任务，最终输出**一个**拼接视频；不是把每个勾选文件变成一个组合任务。用户更换选择、范围或顺序后再次提交，得到第二个独立组合任务。

只选择 B、D 时，任务中只能出现 B、D，顺序以组合列表为准。没有勾选的 A、C 不得出现在请求、计划或输出中。

### 4.3 状态与模式

Tab 切换保留各片段已编辑范围、水印和组合选择，不创建任务、不自动导出。裁剪当前片段与组合成员使用明确 ID，不用数组长度代替选择状态。

「裁剪 / 组合」是操作类型，不等于编码模式 `accurate / normalize / copy`。编码默认值由**本次提交的片段**决定：一个片段默认 `accurate`，多个片段默认 `normalize`。保留用户明确选择的模式；有冲突时提示修正，不静默改变编码或任务类型。

默认输出 profile、水印、帧率、音频、尺寸、特殊媒体限制与旧 `source` 兼容合同继续遵守 Agent 规格。

## 5. 入队与队列交互

编辑区的主操作分别为“加入裁剪队列 / Add trim to queue”和“加入组合队列 / Add combine to queue”。提交成功显示任务类型、jobId 对应的队列项及“已加入队列”，不能宣称导出完成。无需切换到导出页才能继续编辑。

空闲时新任务自动开始；已有任务执行时，新任务追加为 `queued`。导出期间不因全局忙碌而禁用编辑或加入队列，仅在参数无效、依赖不可用或当前提交尚未完成时阻止相应提交。

一次有效提交创建一个任务。请求处理期间按钮防重复点击；main 以 requestId 保证幂等，同一请求重试返回同一 jobId。提交成功后，用户再次主动提交可生成新 requestId，即使内容相同，也视为有意创建另一任务。

复用 `/exports` 展示统一队列，裁剪和组合不各自拥有执行器。等待任务按 FIFO 顺序显示，明确区分当前执行项、等待项和历史结果。

每项至少显示：任务类型、素材/片段摘要、片段数、预计输出时长、输出名称、入队时间、状态，以及运行中的真实阶段与进度。等待项显示“等待中”及等待顺序，不显示虚构的编码进度。

支持取消单个等待或执行中的任务；完成项提供打开输出和 Finder 定位。失败项保留原因，并允许“重新加入队列”：以原快照重新校验后创建新 jobId，追加队尾，保留原失败记录。失败不自动无限重试。

不要求本期批量加入全部裁剪、批量取消、清空等待队列或任务优先级；现有删除终态历史功能保留，删除记录不能删除输出文件。

## 6. 调度、快照与文件保护

### 6.1 单任务执行

main 是任务和调度的唯一权威。任何 UI、IPC 或 Agent 入口提交的导出都经过同一队列，不能并行启动另一套裁剪或组合执行器。

状态主链：

```text
queued → validating → preparing → running → verifying → completed
```

执行失败进入 `failed`；等待任务可直接进入 `cancelled`；活动任务取消进入 `cancelling`，等待所有子进程退出并清理本任务临时资源后才进入 `cancelled`。

`validating / preparing / running / verifying / cancelling` 中最多有一个活动任务。当前任务的验证、发布、取消或失败清理全部结束后，才能启动下一个 `queued` 任务。FFmpeg 退出但最终验证未完成时，仍占用执行位置。

取消等待项必须立即移出可执行集合，无需等它到达队首，也不启动 FFmpeg。并发提交、重复取消、取消与调度竞争不能导致任务重复执行或突破并发上限。一个任务失败或取消后，继续处理下一个，不让拒绝的 Promise 永久卡住队列。

单任务串行约束针对导出任务的整个执行生命周期。预览和探测继续遵守独立的依赖/取消合同，不把它们伪装成导出队列任务，也不承诺系统中同时最多只有一个 FFmpeg 进程。

### 6.2 冻结与重验

入队前校验任务类型、片段数量、素材引用、时间范围、输出配置和依赖。校验失败返回可修复错误，不创建成功入队记录。

入队成功即冻结有序片段、范围、水印、输出 profile、编码设置和输出授权。随后切换 Tab、勾选、排序、改范围、清空聊天或创建下一任务，不改变任何已入队任务。

草稿 revision 变化使尚未提交的 plan 失效；已接受入队的任务不再依赖当前草稿 revision，不因用户继续编辑而失效。队列启动时仍必须重验源文件身份、字体、输出授权和工具可用性。

入队任务保留其所需的 main 素材/字体映射，移除编辑区素材不应提前释放这些引用。外部删除或改动真实源文件时，受影响任务在启动前失败，不能悄悄读取另一份文件。

依赖规则沿用安装规格：入队时缺依赖直接拒绝；等待任务到队首时缺依赖则明确失败，不无限等待安装。运行中的任务保留已捕获的工具路径，设置修改只影响后续任务。

### 6.3 输出与会话

每个任务有独立输出。默认文件名沿用本地时间 `YYYY_MM_DD--HH_mm_ss`，本期取接受入队的时间；扩展名跟随 profile。同秒入队的任务预留不同名称，使用 `_2`、`_3` 等后缀，并在真正发布时再次检查冲突，展示最终实际名称。

显式目标冲突返回 `OUTPUT_CONFLICT`，不能让两个任务共用一次覆盖授权。禁止覆盖源文件及其软/硬链接别名；沿用目标文件系统内临时输出、验证后独占发布规则。取消或失败只清理本任务临时文件。

队列在当前应用会话内保存；导航、隐藏聊天和 renderer 重新获取快照不丢失任务。退出时若有活动或等待任务，提示“继续留在应用 / 取消全部任务并退出”；只有用户选择退出后才取消等待项、停止活动任务并等待清理结束。不承诺重启恢复。

## 7. 接口与代码归属

- `packages/shared/src/index.ts`：增加 `queued` 和明确任务类型的运行时合同；单片段裁剪、多片段组合校验；typed 入队/取消/查询与订阅结果。具体 API 名可复用现有接口，不以新增命名为目的。
- `main/editor-service.ts` 与 `main/index.ts`：素材库与本次任务选择分离，版本校验、不可变快照、幂等入队和统一串行调度。等待顺序由 main 分配，不能由 renderer 的时间戳决定。
- `preload/`：暴露窄 typed bridge，保留现有隔离边界。
- `renderer/store.tsx`、编辑页及导出页：控制 Tab、当前片段、组合成员/顺序与队列状态；通过 `i18n.ts` 提供双语文案。
- `packages/media-core/`：继续接收本次任务的显式有序片段与工具参数，不根据素材库大小选择任务内容。

新请求应显式表明 `trim` 或 `combine`，并校验片段数量一致。旧请求若没有类型，仅按请求自身片段数兼容推导，不读取全局素材库数量。多个重复源片段仍按独立 clipId 处理；不破坏既有 Agent 重复使用素材能力。

手动 UI 与 Agent 使用同一份 main 权威草稿。组合选择作为有序 clipId 集合保存并参与 revision；更新它不能覆盖不相关片段的范围。Agent `plan_export` 的显式 `clipIds` 是该次计划的成员与顺序，不得被 UI 勾选状态或全库素材替换。

Agent `start_export` 返回 jobId 和真实状态，`queued` 时只能说明已排队；`get_export_jobs` 能读到等待状态，`cancel_export` 可取消等待项。明确“分别裁剪并导出”生成独立任务，明确“拼接”生成一个组合任务；只编辑或预览不入队。保持原有 requestId 幂等、路径隐私和工具调用预算限制。

## 8. 验收标准

1. 0、1、2、3、4 个素材分别验证 Tab 状态；1 个时组合不可点击，2 个时两者可选，3 个起显示多选。导入更多素材不强制切换组合。
2. 导入 A、B、C、D，停留裁剪，只给 B 设置范围后入队；请求仅含 B，输出只有 B 的指定区间。
3. A 裁剪入队后继续编辑 B 并入队；两个裁剪任务独立，A 运行时 B 显示等待中。
4. 组合只勾选 B、D，调整为 D、B 顺序并分别设置范围；任务只含 D、B，输出顺序和总时长正确，没有 A、C。
5. 再次选择 A、C 并入队，得到第二个组合任务及独立输出；不改变之前的 D、B 任务。
6. 组合勾选 0 或 1 项无法提交；预览未选文件、导入新文件、切换 Tab 不自动改变组合成员。全选、清空、取消勾选和再次勾选符合第 4 节顺序规则。
7. 混合提交“裁剪 A、组合 B+C、裁剪 D”；按 FIFO 执行，任意时刻活动任务数不超过 1，包括验证、发布和取消清理阶段。
8. 运行任务期间修改草稿、切换模型、导航或清空聊天，已入队请求快照保持不变；下一任务使用自己的设置。
9. 同一 requestId 并发/重试只生成一个任务；用户主动再次提交新 requestId 可以生成第二个任务。旧请求兼容不依赖素材库大小。
10. 取消等待项立即生效且不启动媒体进程；取消活动项必须等退出和清理后才开始下一项。覆盖取消与开始、取消与完成同时发生的竞争。
11. 任务失败后下一项仍能运行；源文件变化、字体不可读、依赖缺失和输出冲突给出准确错误，不改动输入或已有输出。
12. 同秒提交多个任务默认输出名称不同；显式同目标冲突被拒绝；成功必须经过最终验证与发布，不能以 FFmpeg 退出代替完成。
13. 关闭应用时等待任务也触发退出提示；选择留在应用不改变队列，选择取消退出后不残留媒体进程。
14. 通过 mock Agent 验证独立裁剪、选中片段组合、排队状态查询与取消；结果与手动入口共享同一队列，不把“已排队”说成“已完成”。

实施时增加 shared schema 和 main 调度测试，以受控 deferred 执行器检测并发上限、FIFO、幂等与取消竞争；使用临时 lavfi 素材做真实裁剪/组合导出，经 ffprobe 和解码/帧检查验证时长与片段顺序。Electron E2E 覆盖数量边界、多选、Tab 切换、连续入队、队列反馈及中英文。不得使用或修改用户视频。
