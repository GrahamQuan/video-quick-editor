# 多模型配置与聊天切换规格

状态：已实现（2026-09-08）。通过独立临时配置、真实 AI SDK mock 端点和 Electron 交互验证；不代表真实供应商已通过在线兼容性验收。

## 1. 目标与关系

允许保存多个 OpenAI-compatible 模型配置，在聊天面板直接选择，切换后自动记住选择，重启后恢复。一个配置对应一个端点、Model ID 和独立凭证；同一端点可配置多个不同模型。

本文替代 [Agent 视频编辑规格](agent-video-editing.md) 第 7.1 节中“第一期维护一份活动配置”的限制。其余工具白名单、版本化草稿、上下文预算、导出授权和安全边界继续适用。与 [桌面安装包及外部依赖规格](desktop-installation-dependencies.md) 独立实施：模型可用不代表本地媒体依赖可用。

## 2. 当前基础与范围

实施前 ModelStore 仅保存单个 `config` 与 `credentialRef`。现在 `model.json` 保存 version 1 的配置集合及选择，旧格式启动时原子迁移。main 继续使用 AI SDK Core 和 OpenAI-compatible Chat Completions 适配器。

本期增加配置的新增、编辑、删除、列表和活动配置选择。保留单会话聊天和共同编辑草稿，不新增每模型独立会话、跨重启聊天恢复、自动模型路由、失败后自动换模型、配置云同步或密钥导入导出。继续要求配置 API key；匿名端点不在本期新增范围。

“OpenAI-compatible”指 Chat Completions 与 function tools 的接口合同，不限定供应商品牌，不要求 `/models` 可用，也不把任意聊天端点当作支持工具循环的端点。具体 Model ID 由用户填写；预设名称及适配器 API 在实施时验证，不在业务逻辑中绑定模型名称。

## 3. 数据与持久化合同

以下是目标逻辑字段，最终命名与现有 TypeScript 风格保持一致。

| 层级          | 字段                                                                             | 约束                                                                           |
| ------------- | -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 配置集合      | `version`, `revision`, `profiles[]`, `selectedProfileId`                         | 有明确版本；revision 用于写入冲突检测；选择为有效配置 ID 或 null               |
| 单个配置      | `id`, `name`, `provider`, `baseURL`, `modelId`, `contextBudget`, `credentialRef` | ID 稳定且唯一；provider 为 `openai-compatible`；名称用于 UI，Model ID 用于请求 |
| renderer 视图 | 上述非敏感配置、`hasApiKey`                                                      | 不包含 key、credentialRef 或凭证文件路径                                       |
| 单轮执行快照  | profile ID、显示名、端点、模型 ID、预算及内存内的凭证/客户端                     | 在发送请求被接受时固定，不随后续设置变化而改变                                 |

名称去首尾空白，长度 1–80，集合最多 50 项；允许不同配置使用相同 Model ID。允许同名显示名称，选择器同时展示 Model ID，必要时显示端点主机名来区分。端点、Model ID、预算、key 长度沿用现有 schema 的限制。

配置集合由 main 维护，串行处理写入，校验 `expectedRevision`，通过临时文件加原子替换保存。写入失败返回错误并保留旧集合与旧选择，UI 不提前宣称保存成功。列表更新通过 typed IPC 事件同步到设置页和聊天页，renderer 不直接操作文件。

## 4. 设置页交互

- 列出所有配置，显示名称、Model ID、活动标记和是否已配置 key。提供新增、编辑、测试连接、删除操作；key 使用密码输入框。
- 新增配置保存后加入列表；首次保存成为活动配置，之后新增不自动改变已有选择。未填 key 可以保存为待配置项，但不能发起 Agent 请求。
- 编辑配置不改变 ID。未输入新 key 表示保留该项的 key；删除 key 使用明确独立操作，不影响其他项。
- 连接测试针对当前编辑项的表单快照，只做文本、流式和无副作用工具循环；不保存表单、不切换活动项、不发送媒体上下文、不执行剪辑工具。
- 保存只表示保存成功。测试结果明确标为本次测试结果；端点、Model ID 或 key 改变后，不继续展示旧的“已验证”状态。
- 删除非活动项不改变选择。删除活动项后选择列表中第一项；列表为空则选择 null。界面展示新的选择，不自动发送请求，也不因失败自动换模型。删除操作移除该项凭证引用并清理不再被引用的凭证文件。

## 5. 聊天页与切换语义

聊天面板顶部提供带可访问名称的模型选择器，使用配置名称和 Model ID 标识选项；无配置时显示“配置模型 / Configure a model”入口。配置缺少 key 时仍可选择，发送入口明确提示先补全配置。选择器和状态文案覆盖 English / 简体中文，键盘可操作，窄窗口中不遮挡清空和关闭按钮。

选择成功立即持久化 `selectedProfileId`，隐藏面板、导航、重启后恢复。更改活动选择不清除消息、未发送文本、素材、草稿、计划或导出任务。清空聊天仍只清除会话上下文，不删除模型配置或重置选择。

正在回复时允许选择另一个模型；UI 同时显示本轮使用的模型和“下一轮使用”的新选择。本轮全部文本生成、工具循环及正常重试使用同一快照。更改、删除运行中的配置或替换其 key 不取消该轮；已加载到内存的执行快照持续有效，结束后释放。不在不同端点间转发重试请求。

“发送”被接受后先锁定模型快照；含本地路径导入的复合指令也必须在导入前锁定同一选择。缺少活动配置或 key 时，在开始这次自动导入前报错。导入期间切换配置只影响下一次发送，避免一次操作的模型由异步完成顺序决定。

每轮消息标注实际使用的配置名称与 Model ID，历史标注是当时快照，不因后续重命名而改变。切换模型后下一轮重新按所选预算构建上下文，保留当前草稿、用户约束与成对的工具调用/结果；无法容纳时明确报错，禁止截断半组工具消息或重放历史导出。

## 6. IPC 与凭证边界

逻辑接口包括 `listModelProfiles`、`saveModelProfile`、`deleteModelProfile`、`selectModelProfile`、`testModelProfile` 及配置变化订阅。集合修改均携带 expectedRevision；测试可引用配置 ID 以使用该项已有 key，但不能取回 key。所有参数与返回值在 shared 定义 Zod 合同，main 校验 sender、ID、revision 及限制，preload 只暴露 typed API。

- 每项凭证独立经 Electron safeStorage 加密保存；不按主机名共享 key，不把 key 回传 renderer、写入日志或普通配置 JSON。
- 修改 Base URL 后必须为新地址明确输入 key，或清除凭证并保存为未配置状态。不得沿用旧地址的 key，即使两个地址在同一主机但路径前缀不同。
- Base URL 保留路径前缀，拒绝内嵌账号、query、fragment 和完整 completion 路径；远程仅 HTTPS，loopback 可 HTTP，禁止请求重定向。
- 安全存储不可用或某项凭证损坏时，仅将该项标为不可发送；不泄露错误原文中的 key，也不降级明文，不使其他有效配置丢失。
- 用于本轮的 key 只在 main 内存中存在。模型只接收现有最小媒体元数据；新增配置机制不扩大 tools 权限。

## 7. 旧配置迁移

首次读取时识别当前 `{ config, credentialRef }` 格式，将它迁移为单项集合，生成一次稳定 ID，以 Model ID 作为初始显示名称并设为活动项。保留原端点、预算和凭证引用，用户无需重填 key；无需为迁移解密并重写凭证。

迁移须幂等、原子：新集合写入成功前保留可读取的旧文件，不提前删除凭证；失败时保留旧数据并提示重试。无法识别、损坏或来自更高版本的集合不得被空集合覆盖。集合有效但 selectedProfileId 失效时，恢复第一项并显示恢复后的选择；空集合恢复 null。启动恢复不得发起模型请求。

## 8. 验收标准

1. 保存至少两个不同端点和两个同端点不同 Model ID 的配置，列表、编辑、删除互不覆盖；重启后配置与最后选择一致。
2. 从旧单模型配置迁移后可使用原 key，重启多次不重复迁移、不产生重复项；注入写入失败不丢失旧配置。
3. 在聊天中选择 A 后发起真实 SDK mock 工具循环，过程中切到 B：本轮每步仍发往 A，下一轮只发往 B；修改/删除 A 的配置不改变其运行快照。
4. 路径导入期间切换模型，本轮仍使用发送时的选择；初始配置不可发送时不开始自动导入。
5. 切换、隐藏、导航不丢失输入或草稿；清空聊天保留模型选择；历史模型标注不随重命名改变。
6. 用互不相同的测试 key 验证每个端点仅接收其所属 key；路径前缀保留、重定向拒绝、明文 key 不出现在配置视图或日志。
7. 测试连接不切换配置、不保存未提交表单、不执行媒体工具；仅支持文本而不支持工具循环的端点被明确标为测试失败。
8. 活动项被删除、最后一项被删除、凭证缺失/损坏、存储不可用及并发修改均有明确且可恢复的状态。
9. 新模型预算较小导致超限时明确提示，不静默丢失约束、不重复创建导出任务；模型切换不改变既有导出作业。

验证包括 shared schema、配置集合/迁移测试、真实 AI SDK 对 mock Chat Completions 端点的多步测试，以及 Electron 设置页/聊天页交互测试。使用临时 userData 与测试凭证；真实供应商文本、流式和工具循环单独报告，不以 mock 通过宣称线上兼容。实现交付时更新双语 README。

## 9. 本次实现验证（2026-09-08）

- shared schema 覆盖名称/数量/revision 限制和公开视图敏感字段排除。ModelStore 测试覆盖独立凭证、并发冲突、原子保存失败、旧格式幂等迁移及迁移写入失败、损坏/未来版本保留、选择恢复和删除清理。
- 真实 AI SDK 对 mock Chat Completions 的多步测试验证两个端点只收到各自的 key、路径前缀保留；切换及删除活动配置后，本轮客户端继续使用原快照。下一轮应用新预算，超限时不发送网络请求；历史名称保持不变。
- Electron 验证同端点不同模型的新增、选择持久化、保留输入、清空聊天不改变选择；用延迟 ffprobe 在自动导入尚未结束时切换模型，本轮导入后仍发送到原模型，下一轮发送到新模型。
- 连接测试保持无媒体工具、使用表单快照且不写入/切换配置；未保存的新配置不能继承活动项密钥。缺少本地媒体依赖不影响模型配置。
- 未使用用户 API key 调用真实供应商。公开供应商的文本、流式、工具循环和服务端重试行为须在用户授权的在线验收中单独报告。
